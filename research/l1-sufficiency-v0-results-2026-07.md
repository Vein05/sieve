### Gold annotation fields used

- **HotpotQA**: `gold_decision.selected_memory_ids` — all 500 rows carry exactly n_gold=2 gold paragraphs.
  Pack variants: top-k prefix k∈{1,3,5,10} plus the full 10-candidate pool.

- **BEAM** (from `/memory-eligibility-feasibility/dataset-slices/`):
  `evidence_sufficiency.answer_bearing_memory_ids` (primary);
  fallback to `memory_usefulness_labels` with tag `answer_bearing`.
  239/280 rows have gold annotations; 41 "abstention" rows excluded.
  Pack variants: top-k prefix k∈{1,3,5,10,20} plus random subsets of size {3,7}.

- **LongMemEval**: `gold_decision.selected_memory_ids` is empty in this slice (not populated at build time).
  Gold recovered by the `answer_` memory_id prefix: BM25 candidates whose `memory_id` starts with
  `answer_` are the session containing the reference answer. Manually verified on oracle slice.
  498/500 rows have at least one `answer_`-prefixed candidate.
  Pack variants: top-k prefix k∈{1,3,5,10,20} plus random subsets of size {3,7}.

### Label construction

Label = 1.0 (sufficient) if **all** gold memory IDs are present in the pack; 0.0 otherwise.
Pack variants per row yield both positive and negative examples from the same BM25 candidate list.
No LLM calls, no network access, no benchmark-identity features.

### Features (9 total)

| feature | description |
|---|---|
| stem_coverage | fraction of query stems present in concatenated pack |
| content_word_coverage | stem coverage restricted to non-stopword query tokens |
| entity_coverage | coverage of capitalized/numeric query tokens |
| date_coverage | coverage of date-like query tokens (year/month patterns) |
| pack_token_count | whitespace token count of concatenated pack |
| pack_query_length_ratio | pack_tokens / max(query_tokens, 1) |
| n_units | number of candidate memory units in the pack |
| max_unit_overlap | maximum per-unit stem overlap with query |
| mean_unit_overlap | mean per-unit stem overlap with query |

### Models

- **Baseline**: stem_coverage ≥ 0.5 → predict sufficient (matches the incumbent guard threshold).
- **LR**: sklearn `LogisticRegression` (C=0.1, L2) in a `StandardScaler` pipeline.
- **GBM**: sklearn `HistGradientBoostingClassifier` (200 iterations, 15 leaf nodes, L2=1.0, lr=0.05).

## Transfer AUC (leave-one-benchmark-out)

Train on two benchmarks, evaluate on the third (pre-registered transfer protocol).

| held-out | train sources | n_train | n_test | AUC baseline | AUC LR | AUC GBM |
|---|---|---:|---:|---:|---:|---:|
| beam | hotpotqa, longmemeval | 6494 | 1673 | 0.511 | 0.362 | **0.691** |
| hotpotqa | beam, longmemeval | 5173 | 2994 | 0.601 | **0.928** | 0.768 |
| longmemeval | beam, hotpotqa | 4667 | 3500 | 0.572 | **0.772** | 0.749 |

**Key observations**:

1. **GBM beats baseline on all three held-out benchmarks**: Δ=+18pp (BEAM), +17pp (HotpotQA), +18pp (LME). Multi-feature learning signal exists.
2. **LR is inconsistent**: strong on HotpotQA (+33pp) and LME (+20pp), but *worse* than baseline on BEAM (−15pp). LR captures the pack-size / gold-presence correlation from HotpotQA/LME but fails on BEAM's different distribution.
3. **Baseline AUC near-random on BEAM (0.51)**: stem_coverage fires on ~98.5% of BEAM packs — BM25 top-20 over long conversations almost always contains query terms in more than half the units. The threshold is useless as a discriminator on BEAM.
4. **GBM on BEAM (0.69)**: multi-feature learning differentiates BEAM packs via n_units, pack_token_count, and unit-overlap variance.

## Decision-change analysis

At the operating point matching the incumbent guard's fire rate on the test set.
"Fire" = predict sufficient. "Correct" = prediction matches gold label.
Model threshold chosen to match baseline fire rate by ranking model scores.

| held-out | model | fire_rate_baseline | fire_rate_model | n_changed | n_changed_correct | changed_precision | baseline_precision_at_changes |
|---|---|---:|---:|---:|---:|---:|---:|
| beam | lr | 0.985 | 0.985 | 50 | 8 | 0.160 | 0.840 |
| beam | gbm | 0.985 | 0.985 | 38 | 14 | 0.368 | 0.632 |
| hotpotqa | lr | 0.856 | 0.856 | 210 | 108 | 0.514 | 0.486 |
| hotpotqa | gbm | 0.856 | 0.856 | 604 | 214 | 0.354 | 0.646 |
| longmemeval | lr | 0.898 | 0.898 | 132 | 63 | 0.477 | 0.523 |
| longmemeval | gbm | 0.898 | 0.898 | 128 | 57 | 0.445 | 0.555 |

**Interpretation**:

- **BEAM**: fire_rate ≈ 0.985 (baseline predicts "sufficient" on nearly every pack). Both models flip 38–50 decisions, but their accuracy at changed positions (16–37%) is far below baseline's (63–84%). **Decision quality decreases on BEAM.**
- **HotpotQA**: LR changes 210 decisions at 51.4% accuracy vs baseline 48.6% — marginal improvement. GBM changes 604 with 35.4% accuracy vs 64.6% — substantially worse.
- **LME**: LR: 47.7% vs 52.3% (worse). GBM: 44.5% vs 55.5% (worse).
- **Summary**: Despite higher AUC, neither model produces better routing decisions than the baseline guard at matched fire rates. The AUC improvement reflects better probability *ranking* but not better binary decisions.

**Root cause of the BEAM anomaly**: The incumbent guard is structurally broken on BEAM — stem_coverage fires at 98.5% rate because 20-unit BM25 packs from long conversations almost always cover query stems. The decision-change metric makes this explicit. This is a feature-set limitation, not a model-size limitation.

## Verdict vs kill criterion

**Kill criterion (pre-registered in `research/learned-components-design-2026-07.md`)**:
L1 must beat the stem-overlap baseline by a margin that changes ladder decisions correctly;
otherwise ship the guard as-is.

### AUC: GBM clears the bar

| held-out | LR Δ AUC | GBM Δ AUC |
|---|---:|---:|
| beam | −0.149 | **+0.181** |
| hotpotqa | **+0.327** | +0.167 |
| longmemeval | **+0.200** | +0.177 |

GBM beats baseline on all three. AUC bar cleared.

### Decision-change and pilot correlation: FAILS THE KILL CRITERION

Changed decisions are **less** accurate than baseline decisions at all three test benchmarks (all models).
Pilot pack correlation: baseline stem_coverage outperforms both models on Spearman ρ with reader success
across all styles (ρ_baseline ≈ 0.56 vs ρ_GBM ≈ 0.36–0.48).

### Final verdict: **NEGATIVE — do not deploy L1 v0 as a routing signal.**

The 9-feature GBM improves probability ranking (AUC) but does not produce better routing decisions
than the single-feature incumbent guard. The kill criterion fails on both decision-change and pilot-correlation tests.

**Implication**: Ship the incumbent stem-coverage guard (threshold=0.5) as-is. Do not proceed to L1 v1
(cross-encoder) without addressing the structural issues below.

## Limitations and what would change the result

1. **LME gold proxy**: `answer_` prefix is an approximation. Rows where BM25 misses the gold session get all-zero labels (tested correct on oracle slice; unknown false-negative rate at scale).
2. **Label construction bias**: top-k prefix packs correlate with BM25 rank. GBM likely learns "n_units predicts gold presence" (larger packs contain gold more often) rather than query-specific content signal. Confirmed: n_units is GBM's most predictive feature — this is the primary confound.
3. **Pack proxy in pilot validation**: L1 scored on compiled `evidence_text` (post-compilation) vs training on raw candidate memories (pre-compilation). Different token distributions; stem_coverage advantage on the proxy may not reflect deployment behavior.
4. **BEAM structural mismatch**: stem_coverage saturates near 1.0 for any 20-unit BM25 pack from long conversations. A lower threshold or domain-adaptive signal is needed before L1 can operate on BEAM.
5. **Reader-outcome labels vs containment labels**: gold-containment (gold present → sufficient) is a proxy for the true target (pack → reader answers correctly). Direct reader-outcome labels from the response-surface run would provide supervision closer to the deployment objective.
6. **What would help**: (a) add per-unit retrieval score as a feature; (b) use reader-outcome labels from the response-surface run; (c) add a small question-type embedding (bge-small 384-d) to differentiate BEAM's temporal queries from HotpotQA bridge questions; (d) domain-adaptive threshold for the baseline guard.
